# Карта выбора пункта — страница мини-аппы

Это отдельная папка, и она же — репозиторий для GitHub Pages. Внутри
только страница и пункты выдачи: открытые данные обеих служб. Настроек,
заказов и платёжной карты тут нет и быть не должно — они лежат в `data`,
а `data` своим репозиторием не является.

## Что здесь лежит

| | |
|---|---|
| `index.html` | сама карта: Leaflet, тайлы OpenStreetMap, кнопки выбора |
| `плитки/` | пункты выдачи, нарезанные по сетке 0,1° — 5234 файла |
| `свод.json` | сколько где пунктов: кружки с числом при мелком масштабе |

Плитки нарезает `плитки_пунктов.py` из боевых справочников
(`data/fivepost_points.json`, `data/yandex_points.json`). Руками их не
правят: пересобираются сами, следом за справочниками.

## Почему статикой, а не своим сервером

Решение владельца 10 сентября 2026: домашняя машина наружу не торчит.
Живая карта без сервера возможна ровно из-за плиток — браузер просит те,
что попали в видимую рамку, и получает их с того же Pages. Значки
подгружаются по мере движения карты, а падать нечему.

## Как это включить — один раз, руками владельца

1. Завести на GitHub пустой репозиторий (можно приватный — Pages из
   приватного работает на платных планах; на бесплатном нужен открытый).
2. Из этой папки:

   ```
   git remote add origin https://github.com/<кто>/<репозиторий>.git
   git push -u origin master
   ```

3. В настройках репозитория — **Settings → Pages**, источник
   «Deploy from a branch», ветка `master`, папка `/ (root)`. Через
   минуту-другую страница поднимется по адресу
   `https://<кто>.github.io/<репозиторий>/`.
4. Проверить этот адрес в браузере: должна открыться карта с пунктами.
5. Прописать его боту — в `data/support.json`, поле `map_url`:

   ```json
   "map_url": "https://<кто>.github.io/<репозиторий>/"
   ```

6. Перезапустить магазин сторожем (`сторож.поднять`), не руками.

Пока `map_url` пуст, кнопки карты у покупателя нет и разговор идёт
словами, ровно как раньше. Это же и способ выключить карту, если она
начнёт мешать: убрать ссылку.

## Как оно обновляется дальше

Само. Справочники обновляются раз в сутки (`points_refresh.сторож`,
живёт в магазине), и сразу за ними пересобираются плитки и уезжают сюда
`git push` (`выложить_карту.py`). Владелец видит это вестью «Карта
обновлена: мест N» вместе с вестью о справочниках.

Не вышло выложить — придёт «⚠️ Карту выложить не вышло», и это не
пустяк: у покупателей карта осталась вчерашней, а в списках бота пункты
уже свежие.

## Чего делать нельзя

* **Править `index.html` прямо на GitHub.** Правка живёт в этой папке;
  следующая выкладка перезапишет чужую.
* **Класть сюда что-либо из `data`.** Репозиторий открытый.
* **Менять шаг сетки только в одном месте.** `ШАГ` в
  `плитки_пунктов.py` и `ШАГ` в `index.html` обязаны совпадать: иначе
  страница просит плитки, которых нет, и карта пустеет над полным
  справочником.
